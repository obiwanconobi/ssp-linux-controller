01 Executive summary

The client is already a capable editor: connection, chain editing, block parameters, dual NAM/IR, global EQ, and uploads are in place. The gaps are concentrated in the performance layer and the management layer — the parts of the official workflow that live outside the signal chain.

Highest-value quick wins

Start here
  • Tuner — live frequency/cents from root\settings\tuner.
  • VU meters — the data is already read by Device.state(); the modern UI simply never shows it.
  • Input gains and connected-input indicators.
  • Preset level, colour, tempo and a Tap Tempo button.
  • Save As… — save_preset(name) already exists; only the dialog is missing.
  • USB audio mode/status/volume.
  • Clear chain / Load default chain actions.

Larger projects

Plan next
  • Preset library: delete, reorder, bank view, import/export, backup/restore.
  • NAM/PNAM/IR library: rename, delete, reorder, download, dependency checks.
  • MIDI PC map + controllers: channel, PC table, global/preset controllers, learn, Assign 1–4.
  • Connectivity: Wi-Fi configuration, BLE transport, password authentication.
  • Native bundles: preset import/export with dependencies.
The short version A focused “Performance & Setup” release (tuner, meters, input, preset extras, USB, chain actions) would close most of the everyday-user gaps with relatively little new protocol work. The library and MIDI/controller work is larger, but the node model is already there — it is mostly client-side plumbing and UI.
Important No writes were made to the pedal during this audit. Everything below was verified by reading browse root/read root, inspecting the official 2.4.4 firmware strings, and reading the client source. Items marked needs hardware check have known node shapes but unverified write/trigger semantics.

03 Why this matters

These are not obscure protocol corners. They are the features the official app and the pedal’s own screen treat as first-class:

Live performance

The tuner, tap tempo, preset level/colour, VU meters and controller assignments are the things a player touches between songs. Without them the Linux client is a studio editor, not a live controller.

Library ownership

On this unit the pedal exposes 60 presets, 60 NAM amps, 60 NAM drives, 10 PNAM amps, 10 PNAM drives, 50 IRs and 16 VxAmp slots. Uploading is supported, but organising, renaming, deleting and backing up is not — so the library is effectively write-only from the client.

Rig integration

MIDI PC/CC, MIDI clock, the global and per-preset controllers, and Assign 1–4 are how the pedal fits a pedalboard. The nodes are already in the cache; only the UI and a few writes are missing.

System setup

Input gain, Ctrl toe/heel calibration, headphones, ground lift, encoder direction, Wi-Fi and USB audio mode are all exposed as simple float/enum/string nodes. Most are tiny additions with high user value.

04 System, setup & monitoring

The entire root\settings subtree, plus root\usb and the live meters, is absent from the modern UI. These are ordinary nodes and can be read from the existing cache; most writes use the existing Device.write().

Tuner

Missing P0 Effort S–M Verified live

The pedal has a chromatic tuner with selectable A4 reference and a live detected frequency. The client has no tuner UI at all.

Device nodes
root\settings\tuner\on_off · enum ON/OFF
root\settings\tuner\tuner\ref · enum 432 … 448 Hz
root\settings\tuner\tuner\lvl · float, −60…0 dB
root\settings\tuner\tuner\_freq · float, 0…2000 Hz (detected pitch)
  • Suggested UI: a Tuner button in the header or Master panel; a popover with note name, cents deviation, frequency, reference dropdown, input level and an enable switch. Auto-enable while open, restore the previous state on close.
  • Implementation: poll _freq and lvl at ~20–30 Hz on a dedicated reader; do not wait for the 2 s full browse on TCP. Compute the nearest note and cents from the selected reference. _freq is currently skipped by the generic editor because its name starts with _.
  • Caution: verify whether on_off mutes the main output on this firmware; the manual describes tuner activation from footswitch C.

Input gains & connection state

Two independent inputs with digital gain and automatic mono duplication when only one jack is connected.

Device nodes

Expression pedal calibration

Missing P1 Effort S Verified live

Device nodes

root\settings\ctrl\tev · float, 0…100 % (toe)
root\settings\ctrl\_clvl · float, 0…100 % (current position)

Misc setup

Missing P1 Effort S Verified live
Device nodes
root\settings\misc\midi_a · enum MIDI channel 0…15
root\settings\misc\encoder · enum CW/CCW
root\settings\misc\headp · enum STEREO/MONO/L
root\settings\misc\lift · enum ON/OFF
root\settings\misc\factory · action, smp_cfm (factory reset)
  • Suggested UI: Settings → Misc with four compact selectors and a destructive “Factory reset” button.
  • Factory reset clears the NAM, IR and preset lists. Require typed confirmation and offer a backup first. The device action type smp_cfm means “confirm on device”; the client should mirror that confirmation.
  • Action trigger: firmware analysis shows NodeAction::edit() writes run and exec() handles smp/smp_cfm. A likely command is write <path>:{"value":"run"} — verify on hardware before shipping.

Global controllers 1–3

Missing P1 Effort M Verified live

Three global “mctrl” modules, each with a source, MIDI address, learn toggle, and three parameter links with min/max ranges.

Device nodes
root\settings\misc\ctl3 · Global Controller 1
root\settings\misc\ctl4 · Global Controller 2
root\settings\misc\ctl5 · Global Controller 3
per controller: src (Ctrl/MIDI CC), opt1_address (32…127), lrn (ON/OFF), lnk1..3\lnk (parameter path), min/max (0…100 %)
  • Suggested UI: a controller matrix — one row per controller; source/address/learn; three link rows with a searchable parameter picker and min/max sliders.
  • Implementation: the generic editor currently skips item_type=link nodes, so the link target is invisible. Add a dedicated link picker that walks the block tree and writes the parameter path.
  • Learn: set lrn to ON, send MIDI CC to the pedal, then set it back to OFF. The client does not receive MIDI itself; the pedal performs the learn.

VU meters

Partial P0 Effort S Verified live

The data is already read into Device.state() as meter_in/meter_out, but the modern UI never renders it. The legacy UI printed text meters.

Device nodes

root\sys\_meters\_in1 · In 2 peak, −110…0 dB
root\sys\_meters\_out0 · Out 1 peak, −110…0 dB

Identity, alias, Wi-Fi & security fields

Partial P1 Effort S–M Verified live
Device nodes
root\sys\alias · string (device alias)
root\sys\wifi\ssid · string
root\sys\wifi\password · string
root\sys\wifi\state · string (CONNECTED, DISCONNECTED, CONNECTING, DISABLED)
root\sys\pwd · string (device password)
root\sys\key · string (security key)
root\sys\_arch, _author, _license, _logo · read-only info
  • Suggested UI: an About dialog with model, firmware, architecture, author, license and logo; a Network card with SSID/password/state; an alias field; a read-only security-key field.
  • Wi-Fi: there is no scan API in the node tree — only manual SSID/password + state. Writing credentials over Wi-Fi will disconnect the current session; require USB or warn clearly.
  • Password: do not offer changing root\sys\pwd until token authentication is implemented, or the client will lock itself out.
Security observation — read before adding Wi-Fi UI browse root returns the Wi-Fi SSID and password in plaintext, along with root\sys\pwd and root\sys\key. Values are intentionally omitted from this report. Any unauthenticated USB/TCP client can read them. Do not log these nodes, do not include them in screenshots, and keep secrets masked behind a “reveal” control in any future Network panel.

05 Presets & performance

The client can select, rename and save the current preset, but the per-preset performance fields and the preset library are not exposed.

Preset level, colour & tempo

Missing P0 Effort S Verified live

These are per-preset values under root\app\output\pst. The current Master panel edits global volume and global tempo only, and its tempo tooltip says “Patch tempo” — a label/behaviour mismatch.

Device nodes
root\app\output\pst\level · float, −20…+20 dB (per-preset level)
root\app\output\pst\tmp · float, 30…240 BPM (per-preset tempo)
root\app\output\pst\color · hex string, e.g. 001cff (footswitch LED colour)
root\app\output\tempo_bpm · float, 30…240 BPM (global tempo)
root\app\output\vol · float, 0…100 % (global master)
  • Suggested UI: a “Preset” inspector beside the master controls: level slider, colour swatch/picker, tempo field with a Preset / Global selector, and a Tap button. Show both tempos when they differ.
  • Live example: on this pedal the global tempo is 92 BPM while the preset tempo is ~118.5 BPM. The current UI shows only 92 and writes only the global value.
  • Tap tempo: collect 4+ taps client-side, average the interval, then write pst\tmp (or tempo_bpm in Global mode). No device-side tap command is needed.
  • Colour: item_type=color currently renders as a plain text entry under the generic editor; add a colour button/picker that writes six hex digits.

Save As…

Partial P0 Effort S Code + firmware

Device.save_preset(name) already supports a target name and sends {"value": name, "save": "save"}. The UI calls it with no name, so only “save current” exists.

  • Suggested UI: a “Save As…” action in the preset context menu / header, with overwrite warning and the same 63-byte name validation used by rename.
  • Implementation: add a dialog, call save_preset(new_name), refresh the list. Warn when the target slot is occupied.

Clear chain / Load default chain

Missing P0 Effort S Verified live + firmware

The device exposes two per-preset chain actions next to the master output.

Device nodes
root\app\output\c_chain · action smp_cfm — “Clear Chain”
root\app\output\d_chain · action smp_cfm — “Load Default Chain”
  • Suggested UI: a “…” menu on the signal-chain header with both actions, behind a confirmation dialog.
  • Implementation: likely write <path>:{"value":"run"} (firmware NodeAction::edit writes run); verify on hardware. The default matrix is the router’s def field, so the client can preview it.

Preset delete, reorder & bank view

Missing P1 Effort M Protocol + live list
Device data
root\presets · 60 slots, item_type=pst_pst, move=true, size=32768
reorder: dmove root\presets:{"index":N,"index2":M}
delete: dwrite root\presets:{"index":N,"chunk":-1,"value":"<128 zero bytes as hex>"}

  • Delete caution: the documented delete is a zero-filled name chunk; verify on a disposable slot before shipping. Always confirm and offer a backup.
  • Bank layout: the bank/ABC assignment follows list order (3 presets per bank); there is no separate bank node in the PRO tree.

Per-preset controllers 1–3

Missing P1 Effort M Verified live

Each preset has three “mctrl” controllers, each with a source, MIDI address, learn and three parameter links. These are separate from the three global controllers.

Device nodes
root\app\output\pst\ctl1, ctl2, ctl3
same shape as the global controllers: src, opt1_address, lrn, three lnk/min/max groups
  • Suggested UI: a “Controllers” section in the preset inspector, reusing the global controller matrix component.
  • Note: the firmware also refers to these as multi1/multi2/multi4; the live tree names them ctl1..3.

Preset import / export / backup

Missing P2 Effort L Documented

The protocol docs describe native preset bundles with bdinfo.json, dependencies/, preset/, NAM/IR payloads and optional gzip. The client has no chunked download at all.

  • Prerequisite: implement dread (chunked read) and dwrite list import. parse_message() already recognises the dread command prefix.
  • Suggested UI: Backup all / Restore backup / Export preset / Import preset, with progress and dependency validation.
  • Alternative: a client-side JSON snapshot of parameter values is much easier but is not compatible with the official app; label it clearly as a client snapshot.

06 Model & IR libraries

Uploads are solid, but the lists are write-only from the client’s point of view. Every list is move=true and most are gzip payloads, so the same rename/delete/reorder/read primitives apply to all of them.

NAM / PNAM / IR library management

Partial P1 Effort M Verified live
Device lists (live sizes)
root\nam_amp · 60 slots · 1 MiB · gzip
root\nam_drive · 60 slots · 1 MiB · gzip
root\pnam_list · 10 slots · 2 MiB · gzip
root\pnam_drive · 10 slots · 2 MiB · gzip
root\ir_list · 50 slots · 8192 B · no gzip
root\vxamp_list · 16 slots · 12288 B · no gzip
  • Missing operations: rename (same 128-byte name chunk as preset rename), delete (zero-fill), reorder (dmove/dswap), download/export (dread + gunzip when gzip=true), import (already have dwrite framing), and used-by checks.
  • Dependency data: root\presets.used maps parameter paths (amp model, drive model, IR, PNAM) to model names. Use it to show “used by N presets” before delete/overwrite. The live map covers root\app\amp\model, amp\nam2\model, amp\pmodel, drive\model, ir\ir, ir2\ir, etc.
  • Suggested UI: a Library page with tabs Amps / Drives / Impulses / PNAM; list rows with name, used-by count, rename/delete/export actions, drag reorder, and an Import button.
  • Note: exported IRs will be the stored 8192-byte 2048-sample payload, not the original WAV. Exported NAM/PNAM data is the gzipped stored payload; gunzip if you want the original model bytes.

VxAmp library (legacy / secondary engine)

Missing P2 Effort M Needs format check

The tree exposes a VxAmp block and a 16-slot VxAmp list, but all slots are empty on this unit. The PRO normally uses native NAM/PNAM; VxAmp is the proprietary Sonulab/MagicMatch format used by the older StompStation and Amp Studio.

Device nodes
root\app\vxamp · block with model plist → root\vxamp_list
root\vxamp_list · 16 slots · 12288 B · item_type=vxamp
  • Recommendation: do not prioritise until the .vxamp upload format is confirmed. At minimum, show a clear empty-state when the block is added.
  • If implemented: likely the same dwrite list path with 12288-byte payloads and no gzip; verify with a harmless slot.

07 MIDI & controllers

The pedal has a full MIDI implementation (PC, CC, clock) plus three global and three per-preset assignable controllers. The client exposes none of the configuration.

MIDI channel

Missing P0 Effort S Verified live
root\settings\misc\midi_a · enum 0…15

A single selector belongs in the same Misc settings card as encoder direction, headphones and ground lift.

MIDI PC map

Missing P1 Effort M Needs write check

A 60-entry array maps MIDI Program Change numbers to preset indices. On this unit PC 0–29 map 1:1 to the first 30 presets; the rest map to 0.

Device node
root\cpst · type ctrl, src=midipc, ref=root\app\preset, value = 60-element integer array
  • Suggested UI: a table with PC #, target preset, and a “learn” / “set to current” action; show duplicates and unmapped rows.
  • Implementation: likely write root\cpst:{"value":[...]}; verify on hardware before exposing. Do not ship a partial array — read-modify-write the full 60 elements.

Global & preset controllers + learn

Missing P1 Effort M Verified live

Six controllers total: three global (settings\misc\ctl3..5) and three per-preset (app\output\pst\ctl1..3). Each has source, address, learn, and three links.

  • Suggested UI: a shared controller matrix component, used in both Settings (global) and the preset inspector (per-preset).
  • Link picker: the hard part is choosing a parameter path. Walk root\app, show a searchable tree of block/parameter labels, and write the selected path into lnk. Link values in the live tree are double-backslash-escaped (for example root\\app\\drive\\on_off); normalize_path() already collapses doubles, so use it before matching or writing.
  • Learn: toggle lrn=ON, let the user send a CC from their controller, then toggle off. Show _st as live position.

Assign 1–4 (Home F1–F4 quick controls)

Missing P1 Effort M Needs semantics check

The root exposes four assign items; the firmware has Home::showAssign/editAssign, and the manual describes assigning up to four block parameters to the F1–F4 knobs in Home view.

Device nodes
root\assign1 · item_type=assign, value root\app\amp
root\assign2 · value root\app\mod
root\assign3 · value root\app\delay
root\assign4 · value root\app\reverb
  • Open question: the value is a block path, not a parameter path. The parameter-level mapping is likely stored inside the block or the device UI. Verify how editAssign stores the chosen parameter before building a full picker.
  • Minimum viable UI: show/edit the four block targets and document that parameter selection is on-device.

08 Connectivity

USB serial, TCP and mDNS are covered. The official app also supports Bluetooth LE, Wi-Fi configuration and password-protected devices.

Wi-Fi configuration

Missing P1 Effort S–M Verified live

The node tree exposes SSID, password and state, but no scan results. The device uses nmcli internally to connect.

  • Suggested UI: Settings → Network with SSID/password fields, state badge and a “Connect” button. No network picker unless a scan API is found.
  • Caution: changing Wi-Fi while connected over Wi-Fi disconnects the client. Require USB or show a strong warning; keep the old credentials available for rollback.
  • Security: credentials are returned in plaintext by browse root; mask them by default and never log them.

Bluetooth LE transport

Missing P2 Effort XL Documented

The official app supports BLE; the firmware uses BlueZ GATT and the same node protocol. The protocol notes report a 1024-byte atomic packet size for BLE.

  • Implementation: add a BleakTransport implementing the existing Transport interface. Keep the framing identical (command\r\n\0) and packetise writes to the negotiated MTU or 1024 bytes.
  • Unknowns: GATT service/characteristic UUIDs and the advertising name/TXT payload need a BLE scan or a capture of the official app. Plan a discovery step before promising a timeline.

Password / token authentication

Missing P2 Effort L–XL Documented + symbol evidence

The client currently raises AuthenticationRequired when the device asks for a token. The device password field is root\sys\pwd; the security key is root\sys\key.

  • Algorithm: the protocol notes describe a proprietary 64-entry permutation hash with the salt voidxdevteam. The 2.4.4 ELF exports Security::generateHash, generateToken and checkToken, so the algorithm is recoverable by static analysis if password support is wanted.
  • Until then: do not offer setting a password from the client; it would lock the client out.

09 UI polish & protocol primitives

Block EQ response graphs

Polish P2 Effort M Code + live

The global EQ has a draggable response graph; the in-chain Graphic EQ (8 bands) and Parametric EQ (4 bands) fall back to generic sliders. Reuse EqCurveWidget for both. The 8-band EQ has gains only; the parametric EQ has freq/Q/type/slope.

Parallel routing visualisation

Forward-looking P2 Effort L Documented + live

The 2.4.4 router is a single row of 27 cells (blocks and s series links), so the flat chain UI is correct today. The protocol notes say the matrix can encode series/parallel topology; the current UI flattens all rows. If a future firmware exposes multi-row matrices, render the actual graph rather than a flat list.

Protocol primitives still missing

Missing P2 Effort M Documented
  • dread — chunked list download. Required for library export and preset backup. parse_message() already recognises the prefix.
  • dmove — list item reorder. Required for presets and model/IR lists.
  • dswap — seen in firmware strings; swap semantics need checking.
  • Action helper — trigger smp/smp_cfm actions with a confirmation dialog; likely {"value":"run"}.

About dialog & device information

Partial P2 Effort S Verified live

Only name and firmware are shown today. Add an About dialog with _arch (CM4), _author, _license, _id (masked) and _logo. The logo URL is a remote image; prefer a local fallback or the app icon.

13 Security & privacy observations

Sensitive data exposed by the device browse root returns root\sys\wifi\ssid, root\sys\wifi\password, root\sys\pwd and root\sys\key to any connected client over USB or TCP. On this device the Wi-Fi password is non-empty. The values are deliberately omitted here.
  • Do not log the raw browse payload. The app currently logs only the node count, which is good; keep it that way. Any future diagnostics that dump nodes must redact password, pwd and key.
  • Mask in the UI by default. A Network panel should show bullets with a reveal button, not the password in a text entry.
  • Do not offer password changes until token auth works. Writing root\sys\pwd would lock out a client that cannot hash the nonce.
  • Destructive actions need confirmation. Factory reset, clear chain, preset delete, model/IR delete and overwrite all destroy user data. Offer a backup first where possible.
  • Default device has no authentication. The password field is empty on this unit; treat the transport as trusted-local only.
