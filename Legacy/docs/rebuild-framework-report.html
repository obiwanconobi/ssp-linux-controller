01 / Verdict

Build it in Tauri 2. Keep Flutter as the strong alternative.

The decision is close, but not ambiguous. StompStation's differentiator is a visual, tactile, user-modifiable pedalboard — and the web platform is simply the shortest path from an idea to a convincing amp-and-pedal interface. Tauri also puts the protocol in Rust, where serial I/O, ACK-driven uploads, and background polling belong. Flutter is the better answer only if a single-language team or a tablet-first roadmap outweighs end-user skinning.

The important insight: this app's performance challenge is not drawing knobs at 120 fps. It is never blocking the interface while a serial port waits for a NUL byte, while a 2 MiB PNAM upload waits for an ACK, or while the device returns a 603-node tree. The winning architecture separates a headless device engine from a replaceable UI — which is exactly what both finalists make possible.

01 / UI ADVANTAGE

The pedalboard is a styling problem — and CSS is the best styling tool

Tolex, brushed aluminum, chicken-wire grilles, worn labels, cream panels, LEDs, patch cables: these are gradients, borders, shadows, SVG, and type. A web front end gives you direct control over all of it without writing a rendering engine. A skin can be a JSON token file or a CSS override; a user can change the accent, panel finish, knob cap, and pedal chassis without a rebuild.

02 / CORE ADVANTAGE

Rust is a natural home for the protocol

The current core is already a threaded, blocking, byte-oriented client. Rust's ownership model fits the serialized I/O lock, the persistent RX buffer, and the ACK-driven upload state machine. serialport, tokio, mdns-sd, serde_json, flate2, and hound cover every operation the Python client performs today.

03 / PROCESS ADVANTAGE

No GIL, no blocked UI, no shared event loop

The device engine runs independently of the webview. A slow serial read, a reconnect, or a 2 MiB upload cannot freeze a knob animation. The front end receives typed snapshots and deltas over Tauri events; commands go the other way. Backpressure is explicit instead of accidental.

04 / PRODUCT ADVANTAGE

The web ecosystem is the shortest path to a polished desktop tool

Accessible dialogs, virtualized lists, drag-and-drop, keyboard navigation, responsive layout, SVG curves, and animation are solved problems. The same components can be rendered in a browser against a mock device for fast visual iteration — no pedal, no serial port, no special hardware required.

Rust core · illustrative transport and event bridge src-tauri/src/device.rs
// The serial and TCP transports implement one small trait.
pub trait Transport: Send {
    fn write_all(&mut self, bytes: &[u8]) -> Result<(), TransportError>;
    fn read(&mut self, buf: &mut [u8], timeout: Duration) -> Result<usize, TransportError>;
}

pub fn open_serial(path: &str) -> Result<SerialTransport, TransportError> {
    let port = serialport::new(path, 115_200)
        .timeout(Duration::from_millis(250))
        .open()?;
    Ok(SerialTransport { port })
}

// Commands are thin: lock the device, perform one operation, return.
#[tauri::command]
async fn set_block(
    state: tauri::State<'_, AppState>,
    block: String,
    on: bool,
) -> Result<(), String> {
    state.device.lock().await
        .set_block(&block, on).await
        .map_err(|e| e.to_string())
}

// One poller. One event stream. The UI decides what to render.
let handle = app.handle().clone();
tauri::async_runtime::spawn(async move {
    loop {
        let delta = device.tick().await;
        handle.emit("device://state", delta).ok();
        tokio::time::sleep(Duration::from_millis(250)).await;
    }
});

Why it wins here

  • Best possible canvas for a convincing, tactile pedalboard and amp room.
  • User themes and per-pedal skins are cheap to ship and safe to validate.
  • Rust maps cleanly to the existing transport, cache, and upload logic.
  • Small installers, fast startup, and no bundled browser engine.
  • Typed IPC plus a browser-testable UI keeps iteration fast.
  • Built-in updater, signing, and bundling for the three desktop targets.

The honest trade-offs

  • Linux uses WebKitGTK; effects and animation performance vary by distribution and GPU.
  • Two languages: Rust for the core, TypeScript for the interface.
  • CSS can become an unmaintainable design system without token discipline.
  • Webview security requires a locked-down capability file and no remote content.
  • Accessibility is excellent if you use semantic HTML — and easy to break if you don't.

01 / RENDERING ADVANTAGE

CustomPainter is a guitar-pedal UI superpower

A rotary knob with a 270° sweep and a pointer, a VU meter with a real needle, an EQ curve you can drag, a speaker cone, a scratched metal edge: all of these are paths, gradients, and transforms on a canvas. Flutter exposes them directly, and the result is identical on every platform.

02 / TEAM ADVANTAGE

One language from serial port to widget tree

Dart handles sockets, files, gzip, JSON, and isolates without a second runtime. A small team can read the whole system in one language, and widget tests plus golden tests can pin the visual result of a pedal at several sizes.

03 / REACH ADVANTAGE

The tablet remote is not a separate project

The same codebase can target Android and iOS. A network-connected stage remote — setlist, preset stepping, master volume, and a large-format amp view — is a natural second product rather than a rewrite. USB OTG control is possible on Android as a later step.

04 / CONSISTENCY ADVANTAGE

What you test is what every platform runs

There is no “works in WebKitGTK but not WKWebView” class of bug. Fonts, layout, shadows, and hit targets are part of the app, not the operating system. That is valuable for a product with a strong visual identity and a small support team.

Dart · illustrative knob painter and serial service lib/widgets/knob.dart
class KnobPainter extends CustomPainter {
  KnobPainter({required this.value, required this.theme});
  final double value;          // 0.0 .. 1.0
  final StompTheme theme;

  @override
  void paint(Canvas canvas, Size size) {
    final center = size.center(Offset.zero);
    final radius = size.shortestSide / 2;
    const start = math.pi * 0.75;
    const sweep = math.pi * 1.5;
    final angle = start + sweep * value;

    final rect = Rect.fromCircle(center: center, radius: radius - 2);
    canvas.drawArc(rect, start, sweep, false, theme.knobTrack);
    canvas.drawArc(rect, start, angle - start, false, theme.knobValue);

    // Pointer, cap highlight, tick marks, and a value bubble are
    // added here. No platform widgets are involved.
  }

  @override
  bool shouldRepaint(KnobPainter old) =>
      old.value != value || old.theme != theme;
}

// Keep blocking serial I/O out of the UI isolate.

Pick Tauri when

The interface is the product.

The rebuild is a chance to make StompStation feel like a piece of gear, and users should be able to make it theirs.

  • You want shareable pedal skins and a theme editor with minimal friction.
  • You value a small installer, fast startup, and a native-feeling utility.
  • You are comfortable with a Rust core or a staged Python-sidecar migration.
  • Linux is the primary platform and you can test WebKitGTK builds.
  • You want web contributors to help with the UI.
Pick Flutter when

The same pixels must run everywhere.

A tablet or phone companion is part of the product, and the team would rather master one language and one rendering model.

  • You are planning an Android/iOS stage remote from day one.
  • You want golden tests to lock the visual design across platforms.
  • Your team already knows Dart or strongly prefers a single language.
  • You can invest in a bespoke theme/skin editor rather than CSS.
  • Install size is acceptable in exchange for a self-contained runtime.
↗

Don't let the framework decision block the rebuild. The highest-value first deliverable is a headless protocol engine with a replay test harness and a small CLI. Both finalists can sit on top of it. Build that first, in whichever language you choose, and the UI decision becomes reversible.

05 / Wireframes

A pedalboard, not a settings dialog.

These concept wireframes show the Tauri direction; the same information architecture translates cleanly to Flutter widgets. They are deliberately hardware-shaped: the chain is the primary navigation, the amp head carries visual weight, and the selected block opens into a focused editing surface.

The current GTK UI is functional but reads as a grid of form controls. The redesign borrows the visual grammar of a real board: pedal enclosures, amp tolex, speaker grilles, LEDs, and a patch-cable flow from input to output. None of this should obscure the data; every control still has a label, a value, and a keyboard path.

06 / UI blueprint

Build a hardware component kit.

The fastest way to make the rebuild feel designed rather than themed is to stop styling generic form controls. Define a small vocabulary of guitar-hardware components and make every screen compose them. The kit is the design system, the theme surface, and the accessibility contract in one place.

Validate on load, derive contrast checks, and always keep a “reset to default” escape hatch.

State flow
device delta→normalize→diff→store slice→selector→knob

Polling can arrive every 500 ms while the UI updates at 250 ms. Batch deltas into a single animation frame; subscribe each control to a narrow slice; keep an “editing” guard so a poll cannot overwrite a value under the user's finger.

Accessibility is part of the hardware
  • Every knob is a real slider with a name, value, and keyboard step.
  • LED state never relies on color alone; the bypass label is always present.
  • Drag reordering has a keyboard alternative in the block menu.
  • Respect reduced motion; keep needle and meter animation optional.
  • Focus order follows the signal chain, not the DOM's decorative order.
  • Theme contrast is validated before a skin can be saved or shared.
07 / Migration plan

Port the protocol first. Make it pretty second.

The riskiest part of this rebuild is not React or Dart. It is the framing, the ACK state machine, and the device's undocumented edge cases. Freeze those behind a replay harness before a single pedal is drawn. The UI then becomes a client of a stable contract.

00 1 week

Freeze the protocol

Convert current tests and real-device captures into replay fixtures. Record browse snapshots, deltas, block-editor metadata, and upload ACKs. Define the public device state model.

Output: fixture corpus + golden parser tests

Build the headless core

Port transports, framing, cache, router/editor discovery, polling, external-change detection, and the upload state machine. Ship a CLI harness that can connect, browse, set a block, and replay an upload.

08 / Risks

What could go wrong — and the countermeasure.

Most rebuild risk lives in the device layer and the platform edges, not in the choice of component library. Treat the protocol as a compatibility project and the UI as a design project; give each its own acceptance criteria.

RiskWhy it mattersMitigation
Protocol regression High A dropped delimiter or a mishandled final upload chunk can corrupt a model slot or leave the device out of sync. Replay fixtures from real captures, golden byte assertions, and a hardware smoke script that restores every value it changes.
WebKitGTK inconsistency Medium Tauri depends on the system webview on Linux; animations and filters can vary across distributions and GPUs. Test on the target distros, keep effects conservative, provide a “reduced effects” mode, and measure the five-day spike on the oldest supported machine.
Serial ownership conflict Medium The official app and this client can steal each other's read root deltas. Two clients on one pedal is a known failure mode. Single-instance lock, clear “another controller may be connected” warning, and a fast disconnect/reconnect path.
Linux USB permissions Medium CDC-ACM needs a bound driver and the right group. The current app already carries diagnostics for this exact case. Ship a udev rule, detect the missing cdc_acm module, and port the existing --diagnose explanations into the UI.
Theme breakage Low User-authored skins can destroy contrast, hit targets, or layout. Schema validation, a safe token subset, contrast checks, preview-before-apply, and a one-click reset.
Rust learning curve Medium The protocol core is 2,500 lines of Python; a direct port is real work, not a weekend. Keep the core boundary narrow, port against the replay suite, or use a Python sidecar for the first release and rewrite once the UI is proven.
Upload data loss High NAM/PNAM/IR uploads have not been validated on real hardware; the framing has delicate final-chunk rules. Keep the current behaviour exactly, add a read-back/verify step where the device allows it, and test with a harmless slot before enabling overwrite.
