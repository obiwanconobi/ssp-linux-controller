00 / Decision brief

The frame is Tauri 2. The device engine is the product.

The framework question is closed. The rebuild now has two jobs: make the pedal the interface, and make the device layer boringly reliable. Everything else — routing, themes, window chrome — exists to serve those two jobs.

Selected architecture

Tauri 2 Rust device engine + React / TypeScript interface

One application process, two clearly owned worlds. The Rust core speaks the VoidX protocol, owns the transport, and derives stable view models. The React interface renders those models as a pedalboard and never sees a node path.

  • ✓A web UI is the shortest path to convincing pedals, amp tolex, grilles, knobs, and user themes.
  • ✓Rust fits the protocol's serialized I/O, ACK-driven uploads, and long-lived cache.
  • ✓The webview can never block on a serial read, a reconnect, or a 2 MiB upload.
  • ✓Small installers, no bundled Chromium, and a typed IPC boundary that can be tested without a pedal.
Locked · November 2026 · no further framework evaluation
The bar this rebuild must clear

Gear, not forms. Trustworthy enough for a stage.

The old client proved the protocol. The new client must prove the experience: legible at a glance, fast under the hand, and honest about what the device is doing.

  • ✓Usable board in under 1.5 seconds from launch, with the last device reconnectable in one click.
  • ✓Every device write is optimistic but visibly reconciled; a rejection rolls back and explains itself.
  • ✓Uploads, reconnects, and external changes never freeze the interface or lie about completion.
  • ✓A guitarist can run the whole board from the keyboard, and a screen reader can follow the chain.
Measured · Phase 5 acceptance, not aspirational copy
KEEP

The protocol behaviour and domain model.

Framing, the persistent receive buffer, node metadata, router discovery, editor derivation, ACK uploads, external-change detection. Port it, do not redesign it, until the replay suite passes byte-for-byte.

MOVE

All hardware ownership into Rust.

Transports, discovery, polling, uploads, caching, and state reconciliation live behind one typed IPC facade. React receives view models and commands, never sockets or protocol paths.

REIMAGINE

The interface as a piece of gear.

Replace generic sliders and dropdowns with pedals, LEDs, amp faces, speaker cabs, patch links, and a focused amp room. The chain becomes navigation, not a diagram above a form.

The risk is not React rendering a knob at 120 fps; it is a mishandled final NAM chunk, a poll that steals an upload ACK, or a reconnect that resurrects stale state. Build the replay harness and the simulator before the beautiful board.

What changes, and what must not

Runtime

Python + GTK → Rust + Tauri

The protocol library becomes a Rust crate. The UI becomes a web application. No Python runtime ships in the release build.

Boundary

In-process calls → typed IPC

Commands carry opaque control IDs, events carry revisions. The UI never depends on firmware path strings or node types.

Interface

Form grid → hardware kit

One component vocabulary across every screen: pedal shells, knobs, LEDs, amp faces, cabs, meters, and one theme contract.

Failure model

Threads + idle callbacks → actor + revisions

One owner for the device connection. Explicit phases, timeouts, pending writes, and rollback. Backpressure is designed, not accidental.

✓

The protocol is the asset. Every transport and format the current app uses has a mature Rust equivalent: serialport, Tokio TCP, mdns-sd, flate2, hound, serde_json. Nothing in the device layer requires a framework change — only a careful port with a fixture-backed safety net.

02 / Experience design

A pedalboard, not a settings dialog.

The current GTK client is functional, but it reads as a grid of form controls. The redesign borrows the visual grammar of a real board — enclosures, tolex, grilles, LEDs, patch links — and keeps every value, label, and keyboard path intact. The interface should feel like gear and behave like a precise tool.

01 / NAVIGATION The chain is the map.

Blocks are selected on the board, edited underneath it, and expanded in place. The signal path is the primary navigation, not a list of pages.

02 / CONTROL Hardware first, precision always.

Every control has a physical analogue, but also a readable value, keyboard steps, fine adjustment, and a reset.

03 / HONESTY State is always visible.

Connection, transport, sync state, edits, uploads, and external changes have a permanent home. No modal mysteries.

04 / FAILURE Never lie about the device.

Optimistic writes show as pending, reconcile on acknowledgement, and roll back with an explanation. Uploads lock edits, not navigation.

05 / PERFORMANCE One hand stays on the guitar.

Every frequent action has a shortcut, large targets, and a stage layout that reduces the app to preset stepping, bypass, and master level.

06 / OWNERSHIP Themes are content.

A validated token file changes finish, palette, density, and LED behaviour without forking the app or breaking contrast.

Interaction model

Knobs

A hardware gesture with a precise fallback.

  • Drag vertically; 160 px equals the full range. The value bubble appears above the knob while dragging.
  • Shift + drag is 10× finer. The wheel steps by one increment; ↑/↓ do the same.
  • Double-click resets to the device default. Home/End jump to min/max.
  • Every knob is a real role="slider" with a name, value text, min, max, and step for assistive tech.
Chain

Direct manipulation that never lies.

  • Drag a pedal to reorder. A drop indicator shows the exact slot; the device matrix is written once on drop.
  • Fixed slots (amp, delay, reverb) carry a lock affordance and refuse a drag without a dead-looking disabled state.
  • Keyboard: ←/→ select, Ctrl+←/→ move, Space bypass, Enter focus.
  • Optimistic reorder holds until the router write is acknowledged, then reconciles. Rejection restores the prior matrix and toasts the reason.

Save semantics

Explicit save, forgiving experiments.

Parameter changes write to the device immediately, but the preset is only persisted on Save. The title bar tracks Edited → Saving → Saved. The session keeps a local undo/redo stack of control writes; closing with unsaved changes asks once, with “Save”, “Discard”, and “Cancel”. No autosave, ever.

External changes

The device is allowed to disagree.

Polling detects preset or router changes made on the pedal or by another controller. The app rebrowses and re-baselines, then shows a one-line banner: “Changed on device — board reloaded.” It never silently discards a pending write; if a conflict exists, the affected control is marked and the local value is kept until the user accepts the device value.

State design

First run

A connect sheet, not a broken board.

USB ports, discovered devices, and a manual address are offered together. The last device is one click away. Closing the sheet leaves a readable empty shell with a single connect action.

Offline

Last state, clearly frozen.

The board can remain visible with an “Offline” banner and disabled controls so the user can read what was loaded. No fake meters, no optimistic writes, one reconnect button.

Busy

Uploading pauses edits, not navigation.

A persistent banner states the target slot and progress. Write controls disable with a reason; everything else remains inspectable. Cancel stops after the current ACK.

External change

A banner, not a fight.

“Changed on device — board reloaded” links to the activity entry. If a pending local write conflicts, the affected control is marked and the user chooses which value wins.

Unsupported

Explain the missing capability.

A firmware without a router, EQ, or tuner gets a specific placeholder with the last known state and a link to the diagnostic report — never a silent empty panel.

Error

Recoverable by default.

Transient errors toast and retry; rejected writes roll back; connection faults open a card with the error code, “Retry”, “Copy report”, and the activity log.

↔

No hover-only information, no colour-only state. Every LED has an ON/OFF label, every fixed slot has a lock icon and text, every drag action has a keyboard equivalent, and every graph has a numeric path. Accessibility is designed into the component kit rather than audited in at the end.

Knob assignment

Drive / Distortion

KLONE · auto · 3 of 5 continuous controls

Also reachable in the inspector

Prototype values are local. In the app each knob binds to a ControlView from the actor and writes through set_control; the inspector and the shell share one ViewId, so editing either updates both. Bypassed shells keep their knobs live, exactly like a real pedal. The write gateway coalesces at 50 ms and always sends the final value on release. The auto map is a UI decision, not a device one: the priority table ranks the parameters a player reaches for, aliases catch firmware naming differences, and an override is stored per block type without ever touching the preset.

  return eligible
    .map((c, order) => ({
      c, score: score(c, PRIORITY[block.family], order),
    }))
    .sort((a, b) => b.score - a.score)
    .slice(0, 3)
    .map(toKnobTarget);
}
  • Stable by design. Recomputed only when the block type, model type, or control visibility changes — never on a value tick.
  • Parametric aware. The first three visible pfloat controls win, with the model's vname labels, so a PNAM's Drive/Tone/Level replace the legacy stack.
  • Overrides are UI state. Stored by block type in settings; the device and the preset never see them.
  • One write path. Shell and inspector share set_control, pending state, and rollback.
  • No phantom controls. Two eligible parameters means two knobs; the shell never pads with a disabled knob.

04 / Technical architecture

One owner for the pedal. One typed boundary for the UI.

The device engine is a headless actor. It owns the transport, the node cache, the poller, and the upload state machine. The React app consumes derived view models and sends commands through generated bindings. No socket, path, or protocol byte ever reaches the webview.

PRINCIPLE 01

Single owner.

Exactly one task holds the transport and mutates device state. Commands queue; polls and uploads share the same schedule. No mutex around a socket, no ACK theft.

PRINCIPLE 02

View models, not paths.

Rust derives presets, chain slots, controls, and library rows. The UI receives opaque IDs and domain-specific types, so firmware path changes never ripple into React.

PRINCIPLE 03

Revisions, not hope.

Every snapshot and patch carries a monotonic revision. A gap triggers a refetch. Pending writes have explicit lifetimes and rollback, never “probably applied”.

The device actor

The actor runs on a dedicated OS thread with a current-thread Tokio runtime. Blocking serial reads are acceptable there because protocol I/O is intentionally serialized: one frame in, one frame out, then the next command. The Tauri runtime stays responsive because it only awaits oneshot replies and forwards events.

  • Command queue. UI writes, polls, uploads, and tuner reads all enter one mpsc channel.
  • One deadline. Polls, upload steps, and reconnect backoff share a scheduler; an upload pauses polling instead of racing it.
  • Reply per write. Each command carries a oneshot; the UI gets a typed ack or a typed error, not a timeout guess.
  • Event sink trait. The actor emits through a trait, so CLI tests and the simulator use the same core without Tauri.

Security, persistence, platform edges

Security

Local, typed, and closed by default.

  • No remote content. CSP default-src 'self'; no remote fonts, scripts, or frames. The webview only loads the bundled UI.
  • Minimum capabilities. One main window; dialog-scoped file read; no shell, no arbitrary fs, no HTTP server.
  • Serial allowlist. /dev/ttyACM*, /dev/ttyUSB*, COM*, cu.*; manual TCP accepts host:port only.
  • Theme validation. JSON schema, hex-only colours, contrast checks, no URLs or CSS injection.
  • Signed updates. Tauri updater signatures verified; stable/beta channels; no silent downgrade.
  • Redacted diagnostics. Copy report strips user paths and serial numbers unless the user opts in.

Small, local, and recoverable.

  • Store. tauri-plugin-store JSON for theme, density, last transport, recents, favorites; window state via the window-state plugin.

The upload dossier

Uploads are the highest-risk device operation. They run one chunk at a time, wait for the device's next-chunk ACK, and treat a slot mismatch or rejection as fatal. The exact framing below is not an implementation suggestion; it is the compatibility contract.

NAM · .nam

1 MiB slot, gzip, final marker.

  • Zero-pad the raw model to 1,048,576 bytes.
  • Gzip at level 6.
  • Chunk 0: 128-byte UTF-8 name, NUL-padded.
  • Data: 1024 raw bytes per chunk, hex-encoded.
  • Final tail + literal "gz" + "00" pairs, exactly 2048 characters.
  • If the tail is exactly 1024 bytes, send it normally, then a marker-only 2048-character chunk.
PNAM · .pnam

2 MiB list size, same framing.

  • Resolve the target list's size; default to 2,097,152 bytes.
  • Zero-pad, gzip level 6, identical name/data/final-marker rules.
  • After upload, the model's config.params appear as pfloat controls.
  • Map normalized 0..1 values to vmin..vmax; hide visible:false.
  • Replace the legacy tone rows with the model's named knobs.
IR · .wav

2048 samples, float32, no gzip.

  • Read the first channel only; take at most 2048 samples; pad with zeros.
  • PCM 8/16/24/32-bit. 24-bit scale: int24 / 2^23 × 0.3191413049364811.
  • Pack little-endian float32: 8192 bytes.
  • Chunk 0: 128-byte name. Chunks 1–8: 1024 bytes each.
  • No "gz" marker. Compressed WAVs are rejected.
Final NAM chunk · exact stomp-upload/src/nam.rs
// Total value string must be exactly 2048 hex/marker chars.
fn final_value(tail: &[u8]) -> String {
    // 2 chars per tail byte + 2 for "gz" + 2 per padding pair.
    let pad_pairs = 1024.saturating_sub(tail.len() + 1);
    format!("{}gz{}", hex::encode(tail), "00".repeat(pad_pairs))
}

fn marker_value() -> String {
    format!("gz{}", "00".repeat(1023)) // 2048 chars
}

// ACK contract: { "index": slot, "chunk": next }.
// chunk -1 = complete; index -1 = rejected; wrong index = fatal;
// a repeated current chunk is tolerated; any other next chunk aborts.

Why the edge cases matter

  • Full tail. A 1024-byte gzip tail cannot carry the two-character marker in the same chunk. The current client sends the full chunk, then a marker-only chunk. Dropping this path corrupts uploads at a specific payload size.
  • Exact final length. The device validates the 2048-character final value. One missing "00" pair is a rejected upload, not a harmless truncation.
  • Name padding. The 128-byte name is part of the list element. Preset rename uses the same chunked write path with a 63-byte limit.
  • ACK ownership. A poll between chunks can consume the ACK and hang the upload. Pausing the poller is not an optimization; it is correctness.
  • Slot identity. The ACK carries the slot index. A mismatch means the device wrote somewhere unexpected; abort and refresh, do not retry blindly.

Replay harness

A fixture is a scripted transport: a list of expected outgoing bytes, the reply bytes, and an optional delay or drop. Tests drive the real actor, not a mock of the actor. The CLI can replay a fixture and diff the entire event stream. This is how the port stays honest while the UI moves ahead.

Scripted transport crates/stomp-transport/src/scripted.rs
pub struct Step {
    pub expect: Vec<u8>,
    pub reply: Vec<u8>,
    pub delay_ms: u64,
    pub drop_reply: bool,
}

// On write: assert bytes == step.expect, queue step.reply.
// On read: return reply (or timeout when dropped), then advance.

Differential oracle

During the port, generate expected write bytes from the Python client once, commit them as binary fixtures, and assert the Rust client produces identical bytes. This catches float formatting, JSON key order, backslash escaping, name padding, and the final upload marker.

  • Write parity for preset load/save/rename, block toggle, router edit, EQ write, and every upload chunk.
  • State parity for the derived snapshot: same preset, chain slots, labels, control values, and library rows.
  • Error parity for timeout, rejected slot, wrong slot, bad ACK, partial frame, and closed socket.
✱

Do not “clean up” the protocol during the port. If a rule looks redundant, preserve it and add a comment with the fixture that proves it. Cleanup happens after 1.0, against a replay suite that can prove the change is safe.

Never break these

  • The NUL terminator or the CRLF before it.
  • The persistent receive buffer across requests.
  • The first-colon split of response lines.
  • Router geometry and fixed positions.
  • Block ancestor enablers after a router write.
  • 128-byte name padding and the 63-byte preset-name limit.
  • 1 MiB / 2 MiB padding and gzip level 6.
  • The 2048-character final NAM/PNAM value.
  • Polling pause during uploads.
  • External-change rebrowse and re-baseline.
07 / Risks & decisions

What could go wrong — and the countermeasure.

Most rebuild risk lives in the device layer and the platform edges, not in the component library. Treat the protocol as a compatibility project and the UI as a design project; give each its own acceptance criteria and its own early warnings.

Protocol quick reference
