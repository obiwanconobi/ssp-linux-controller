# StompStation 0.6.0 plan

Changes requested after the 0.5.0 release. Keep this list in delivery order:
the export/import work depends on the Library download path, and the
Parametric EQ GUI should reuse the Global EQ graph.

The reference export is `docs/Brave.zip`, exported from the official
StompStation PRO app on firmware 2.5.3. It is a local reference archive and is
intentionally **not committed** because it contains third-party NAM/PNAM/IR
captures. Keep it locally for implementation and testing; do not publish it.

## 1. Input gain and input connection in Settings

Add the four input controls from the official app to **Settings → Audio &
pedal**:

| Control | Device node | Type |
| --- | --- | --- |
| In 1 digital gain | `root\settings\input\gain1` | float, dB |
| In 2 digital gain | `root\settings\input\gain2` | float, dB |
| In 1 connection | `root\settings\input\_connected1` | enum `YES` / `NO` |
| In 2 connection | `root\settings\input\_connected2` | enum `YES` / `NO` |

- Digital gain should use the existing control/knob pattern and show dB.
- Connection state should be a read-only, clearly labelled chip; do not invent a
  write for it.
- Confirm the actual gain range, step, and whether the two inputs are
  independent before finalising the UI.
- Add store mappings, optimistic-write/conflict handling, simulator nodes, and
  tests.

## 2. Make the Add-block selector scroll

The Add-block menu can extend past the viewport on short screens.

- Cap the menu height relative to the window (`max-height: min(60vh, …)`).
- Enable vertical scrolling inside the list.
- Keep keyboard navigation and type-ahead working.
- Add a Playwright check at a short viewport (for example 800×600) that opens
  the menu, scrolls to the last item, selects it, and confirms the block is
  added.

## 3. Parametric EQ graph

Add a graph editor for the Parametric EQ block, similar to Global EQ:

- Show the block's frequency response curve and one draggable node per band.
- Reuse the Global EQ graph primitives: drag, keyboard arrows, reset, selected
  band highlighting, and numeric cards.
- Map the Parametric EQ block's band values into the same view model without
  changing the Global EQ path (`root\app\output\global_eq`).
- Keep the existing knob/control list in sync with the graph.
- Add accessibility checks and a visual baseline for the Parametric EQ surface.

## 4. Preset export

Recreate the official app's preset archive format. `Brave.zip` contains:

```text
bdinfo.json
preset/Brave.pst
dependencies/root/nam_drive/TTS Corn G2 - S00 T00 V10 - A2.nam
dependencies/root/pnam_drive/TTS Corn G2.pnam
dependencies/root/nam_amp/Match Brave Hi D 2.nam
dependencies/root/ir_list/TJ3 G10S50 2x10 SM545.wav
```

`bdinfo.json` is the manifest:

```json
{
  "applicationName": "StompStation PRO",
  "author": "SONULAB Audio Systems",
  "version": "2.5.3",
  "preset": {
    "name": "Brave",
    "extension": "pst",
    "nodePath": "root\\presets",
    "archivePath": "preset/Brave.pst"
  },
  "dependencies": [
    {
      "name": "Match Brave Hi D 2",
      "extension": "nam",
      "nodePath": "root\\nam_amp",
      "archivePath": "dependencies/root/nam_amp/Match Brave Hi D 2.nam"
    }
  ]
}
```

### `.pst` format

`Brave.pst` is a 32 KiB file containing CRLF-separated lines of:

```text
root\app\router:{"value":[...]}
root\app\drive\model:{"value":"..."}
root\app\drive\on_off:{"value":"ON"}
root\app\output\pst\ctl1\lnk3\max:{"value":100.000000}
```

The trailing space after the last line is NUL padding to the fixed file size.
The reference file contains 248 preset paths under `root\app\...`; it does not
contain global settings such as input gain or tuner state.

### Export design

1. Serialize the current preset's `root\app\...` paths in the same
   `path:{"value":...}` shape and line order used by the official app.
2. Resolve model and IR references to files in the capture lists.
3. Download any referenced files that are not already available locally.
4. Write `bdinfo.json` with the preset name, extension, node path, archive path,
   and one dependency entry per referenced file.
5. Zip the manifest, `.pst`, and dependencies using the same relative paths.
6. Offer a save location and never overwrite without confirmation.
7. Validate the archive by re-opening it and comparing the manifest, preset
   paths, and dependency sizes.

Open questions to resolve against the reference:

- exact `.pst` line ordering and whether 32 KiB is fixed for every preset;
- whether missing dependencies are omitted, replaced by a placeholder, or block
  the export;
- whether preset-specific global controls under `root\app\output\pst` are always
  included;
- the official app's behaviour when two dependencies have the same name.

## 5. Preset import

Implement the inverse of export using the same archive contract.

1. Accept a `.zip` selected by the user.
2. Reject paths outside `preset/` and `dependencies/` (zip-slip protection).
3. Read and validate `bdinfo.json`:
   - `applicationName` and format version;
   - preset extension and node path;
   - every `archivePath` exists and every dependency node path is in the
     allowed capture lists.
4. Parse the `.pst` file and reject any path outside the allowed preset nodes.
   Strip NUL padding and tolerate CRLF/LF.
5. Show a preflight summary: preset name, chain changes, dependencies,
   overwrite targets, and any missing/untrusted entries.
6. Upload dependencies first through the existing validated upload path, with
   the normal size/format checks.
7. Apply the preset nodes only after all dependencies succeed.
8. Refresh the snapshot and library, select the imported preset, and keep a
   recovery path if a write fails partway through.
9. Do not import global settings, actions, hidden paths, or arbitrary files.

Test with `Brave.zip` and with a deliberately malformed archive before testing
on hardware. Import must be idempotent enough to retry after a cancelled
dependency upload.

## 6. Library file download

Add download for `.nam`, `.pnam`, and `.wav`/IR entries from the device lists.

- Read the selected list slot through the device's `dread` chunk protocol.
- Reassemble chunks, verify the expected size, and write the original file with
  a safe local name.
- Show progress and allow cancel at chunk boundaries.
- Never overwrite an existing local file without a Save As confirmation.
- Handle empty slots, missing lists, and a device disconnect mid-download.
- Add simulator tests and a hardware pass for each list type.

This is a prerequisite for preset export dependencies. It also gives users a
way to retrieve captures without using the official app.

## Suggested order

1. Library file download (builds the dependency reader).
2. Preset export.
3. Preset import, tested against `Brave.zip`.
4. Input gain/connection settings (independent, can be done in parallel).
5. Add-block selector scrolling.
6. Parametric EQ graph.

## Release checks

- [ ] Export/import round-trip on the same firmware.
- [ ] `Brave.zip` imports successfully on a scratch/backed-up device.
- [ ] An edited preset exports and re-imports with identical values.
- [ ] Corrupt/malicious archives are rejected before any write.
- [ ] Download works for NAM, PNAM, and IR.
- [ ] Input gain and connection state survive refresh and preset reload.
- [ ] Add-block menu is usable at 800×600.
- [ ] Parametric EQ graph is keyboard-operable and covered by axe/visual tests.
- [ ] No regression in the existing 0.5.0 test suites.
